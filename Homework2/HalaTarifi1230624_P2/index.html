A Slow Sensor in the Loop

Module P2 explores what happens when a PID controller gets its feedback from a sensor that takes time to catch up.

Predict, then check

With the PID gains held fixed, what will happen to the true output when the sensor time constant increases from 0.08 s to 2.00 s?

A slow sensor reports a value below the rising true output. The measured error stays positive longer, so the controller keeps driving the plant even as the true output approaches or passes the setpoint. Delayed feedback during the correction can produce repeated swings.

Both runs use Kp = 2.00, Ki = 2.00, and Kd = 0.15. The graphs share a vertical scale.

Model and feedback

The plant uses the assignment’s reference values K = 1 and τp = 1 s. The loop starts at rest and the setpoint steps to 1 at t = 0.

Plantdy/dt = (u − y) / τp
Sensordym/dt = (y − ym) / τs
PIDe = r − ym
u = Kp·e + Ki·∫e dt + Kd·de/dt

Fourth-order Runge–Kutta (RK4) advances the plant, sensor, and error integral together every 0.002 s. For the constant setpoint after the step, de/dt = −dym/dt.

The stability label comes from the continuous-time loop equations. For this plant, the oscillation boundary is Ki = (1 + τs + Kd)(1 + Kp)/τs. At that boundary oscillations persist, and above it they grow in this ideal model with an unconstrained control signal.
